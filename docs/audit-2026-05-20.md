## 1. CRITICAL

### 1.1 Stock movements missing 'sell' audit trail

`stock_movements` has **zero** records with `type='sell'`, but there are **277 active sales** totaling 379 units sold.

| Movement type | Count |
|---|---|
| restock | 776 |
| correction | 60 |
| transfer_in | 40 |
| transfer_out | 40 |
| void | 4 |
| **sell** | **0** |

`executeSaleFIFO()` is called in `sales/group/route.ts` (line 100) which should create sell movements, but no sell records exist. Without sell movements, it is impossible to trace which batch a sale depleted, making inventory reconciliation and cost-of-goods-sold tracking unreliable.

**Root cause:** `executeSaleFIFO()` in `src/lib/inventory.ts` likely decrements batch quantities directly but does not create `stock_movements` records with `type='sell'`.

**Risk:** Audit failure, inability to reconcile inventory, unreliable cost tracking.

### 1.2 Missing `payment_method` migration

`payment_method` is referenced in **7 source files** but **no migration** adds the column to the `sales` table.

Files affected: `my-sales/page.tsx`, `sales/group/route.ts`, `sales/export/route.ts`, `cron/weekly-report/route.ts`, `reports/send-email/route.ts`, `reports/export/route.ts`, `admin/sales/page.tsx`

If the database is ever recreated from migrations (`supabase db reset`), all queries selecting `payment_method` will fail. The column exists on the live database (added via dashboard/SQL editor) but is not reproducible.

**Fix:** Add migration `00024_add_payment_method.sql`:
```sql
ALTER TABLE sales ADD COLUMN IF NOT EXISTS payment_method text DEFAULT 'cash';
```

## 3. MEDIUM

### 3.1 payment_method display inconsistency

| View | Display logic |
|---|---|
| My Sales | `card` → Карта, everything else → В брой (2 values) |
| Export | `card` → Карта, `transfer` → Превод, default → Кеш (3 values) |
| Admin sales | `card` vs non-card (groups transfer with cash) |

If `transfer` (банков превод) payments exist, My Sales mislabels them as "В брой".

### 3.2 One-time `quantity_on_hand` sync without trigger

Migration 00023 syncs `quantity_on_hand` from `stock_batches` but it's a one-time UPDATE. Future stock changes will cause drift. A DB trigger or application-level sync is needed.

### 3.3 30 active products with zero stock

30 products have `status='active'` but 0 total stock across all batches. Should be either restocked or marked inactive.

### 3.4 1 duplicate product name

"Кинезиолента за гръб и рамене" exists twice with different IDs.
